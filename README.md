# OpenBEXI Timeline

Version **2.9.1** · [Release notes](docs/release-2.9.1.md).

Explore events, sessions and activity histories in Timeline, Table, Split and 3D
views. Search, filter and group records, navigate through time, and inspect their
details. Use local JSON datasets, the indexed Python server for progressive
loading, or the Java server for managed data and administration.

Save named views, share a demo's exact time range and filters, and export filtered
table results as CSV. On small screens, **More** keeps secondary controls within reach.

## Quick start

**Windows:** download the installer from the [latest release](https://github.com/arcazj/openbexi_timeline/releases/latest).
It includes Java and browser dependencies. See [Windows installation](docs/windows-installation.md).

**Python backend (2.8):** see [installation, configuration and benchmarks](docs/python-server.md).
The Python service uses the existing UI and supports HBDS administration. Java
remains available for managed data and other providers.

**HBDS configuration:** models, namespaces, sources and tabs now live under
[`HBDS/`](HBDS/README.md). Open **Settings → HBDS Editor** to edit a deployment.
The current model preview, namespace and tab controls share one workspace, with
clearly highlighted editing sections. On the local running server, the editor
connects automatically without a token prompt or Connect button. Operational configurations
remain private; generic templates are explicitly allowlisted for Git.

Install **Node.js 24**, then run:

```sh
npm ci
npm run demo
```

Open [the local demo](http://localhost:8780/demos.html). The supplied datasets run
without a Java server. For connected data, see [server setup](docs/connected-diagnostics.md)
and [the REST API guide](docs/rest-api.md).

The local collector module lives in `GCS_data_collector/` and shares the namespace
YAML and models in `HBDS/`. See the [namespace setup and startup commands](HBDS/README.md).
The default workspace loads the committed earthquake and volcano samples with
`HBDS/models/geoscience_demo.json`.
Each timeline has its own HBDS workspace selecting namespace files, a service and
tabs. Both server launchers default to `HBDS/workspace.json`;
`HBDS/GEO_Workspace.json` loads live data generated by `openbexi_quake` under
`/data/earthquake` and `/data/volcano`, using `HBDS/models/geoscience.json`.
The live data remains outside Git and release packages. The initial **All**
view includes both namespaces; their buttons above the filters select individual sources.
The **by_namespace** preset groups all events by namespace. See the
[shared workspace startup commands](HBDS/README.md#listeners-and-startup).

Server logs default to readable INFO summaries and WARNING/SEVERE diagnostics.
**Settings > Trace level** selects INFO (all three levels), WARNING (warnings and
errors), or ERROR (errors only) for this browser's timeline messages and requests.
The choice is saved locally and takes effect without reloading records. Settings
also displays the installed UI version above the sections.
GET URLs and scan details require DEBUG/FINE logging; see [logging options](docs/connected-diagnostics.md#log-levels-and-readable-summaries).
