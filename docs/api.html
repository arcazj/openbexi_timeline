OpenBEXI Timeline API

Offline reference · Swagger 2.0 · API contract 1.0.0

This page describes the checked-in specification. The browser application is version 1.1; the API contract has a separate version.

The specification declares HTTPS host openbexi_timeline.swagger.io and base path /. This does not confirm a reachable service. Local file-backed demos do not provide this API, and this page makes no network requests.

Get sessions by zone

GET /sessions/{startDate}/{endDate}/{filter}/{search}/{userAccess}

Returns sessions between the requested start and end dates. Operation ID: getSessionByZone. Response media type: application/json.

All parameters are required path parameters. Encode each value as a URL path component.

ParameterTypeDescription
startDatestring, date-timeStart date in ISO format.
endDatestring, date-timeEnd date in ISO format.
filterstringCriteria used to filter events.
searchstringKeyword used to search events.
userAccessstring enumread, write, or admin. This parameter is not proof of server authorization.

The specification does not define a filter expression grammar or an empty-value convention for these required parameters.

Responses

StatusMeaningBody
200Successful operationResponse object.
400Invalid inputNo schema specified.
401UnauthorizedNo schema specified.

Response declares status (string), message (string), and data (one Object, not an array). No required-property list is provided.

Object declares id (integer, int64), type (string), label (string), and startDate (string, date). The request bounds use date-time, while this response property uses date.

Security definitions

The contract defines OAuth 2 implicit flow as sessionstore_auth, with authorization URL https://localhost:8443/ and scopes write:sessions and read:sessions. It also defines the api_key request header.

Neither global nor operation-level security requirements are attached to this endpoint in the checked-in file. Check authentication behavior against the actual deployed server.

Specification scope

Only the GET operation above is defined. Comments mention other operations, but no POST or DELETE contract is supplied. This offline page has no “Try it out” action.
