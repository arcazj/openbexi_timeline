# OpenBEXI Timeline 2.4.0

Model editing now groups work into Overview, Data, Appearance, Filters and Access.
Managed models have per-model administrator, read/write and read-only grants,
isolated configuration documents, model-owned filters and saved configuration
history. Private clones inherit their source model's scope. Public examples and
local import, preview and export remain available.

Optional AI assistance supports explanations, generation and repair through
configured OpenAI, Anthropic, Hugging Face, compatible and local providers.
Vision-capable models can use a timeline image as a reference. Proposals are
validated and shown with a diff and preview; accepting edits the draft, and
saving remains explicit. Provider keys stay on the server. AI supports model
JSON/YAML; source and deployment YAML remain manual.

## Compatibility and upgrade

**The JSON metadata structure of events, sessions and activities is unchanged.**
Existing fields, types, nesting, unknown metadata and null/absent distinctions
remain supported. Ownership, grants, entitlements, history and AI state live in
separate stores. See the [fixed compatibility contract](event-session-contract.md).

Deploy browser assets and server classes together. Existing unscoped datasets
retain their service-token behavior. Follow [model access](model-access.md) to
provision users and scope models; legacy writer/reader tokens cannot bypass
explicit grants. Back up the whole private API data directory. Deleted dataset
IDs remain reserved. One managed model currently binds to one dataset.

AI is disabled until the operator configures providers and workspace eligibility;
see [AI assistance](ai-assistance.md). Entitlements distinguish community,
commercial and verified student/researcher/charity/nonprofit exemptions, independently
of model permissions. The gate currently controls AI. Billing, automatic
eligibility verification and federated login are not implemented.

See the [licensing guide](commercial-licensing.md) and

The [HBDS design](design/2.4/README.md) includes importable JSON, diagrams, an

capabilities beyond the implemented API. README remains a concise entry point.

Package, browser, Help and Maven versions are **2.4.0**; the API contract remains
**1.0.0**. The reviewed source archive is generated by `npm run release:source`.

  passed in focused checks.

  or errors; Maven verification and packaging used JDK 21 with the Java 17 target.
- Editor browser checks: **54 cases passed** across desktop and narrow layouts,
  including phone-width captures, YAML model saves, conflicts and delayed saves.
- Real browser-to-Java integration: **six checks passed**, including a local mock
  AI image proposal and exact preservation of all **27** original item payloads.
- Static-site verification: **14 demo flows passed** across all seven datasets at
  desktop and narrow widths, including the model editor under a path prefix.
- Generated schemas, API specification, demo models and resource checks passed.
  HBDS core/semantic validation, existing importers, YAML round-trip and actual
  HBDS viewer checks passed for **26 classes, 191 attributes and 44 links**.
- Broader timeline browser run: **200 passed**, **seven existing skips**, and one
  initial resize-readiness failure. The test sampled the camera before the
  viewport's resize debounce completed. After correcting its readiness checks,
  all **six** related desktop/narrow cases and **three** repeated narrow cases

  Combined with the editor checks, **255 distinct browser cases** passed across
  the suite and focused follow-ups, with seven skips.

AI provider tests use local mock services. They do not verify a live provider
account, billing, model quality or account-specific availability.

The Event schema and original item sources remain unchanged. HBDS schema and

license, third-party notices and the byte-identical historical GPL text.
